# Guide — 7-Phase Design Journey

Navigate the complete UX design process with confidence. 30 ordered steps across 7 numbered phases, plus 3 utility commands — each grounded in NNG methodology, the Double Diamond, IDEO design thinking, and Lean UX. Every phase has a UX goal, a commercial milestone, and a clear exit gate.

## Process Foundation

The 7-phase system integrates four established design processes:

**NNG Design Thinking**: Empathize > Define > Ideate > Prototype > Test > Implement (mapped to Understand > Explore > Materialize)

**Double Diamond**: Discover > Define > Develop > Deliver (diverge-converge twice: problem space then solution space)

**IDEO Design Thinking**: Inspiration > Ideation > Implementation (human-centered, iterative, prototype-driven)

**Lean UX**: Think > Make > Check (hypothesis-driven, minimum viable design, validated learning)

**Visual Design Process**: Direction & Moodboarding > Information Architecture > Wireframing > Visual Direction > Quality Assessment > Token Foundation > Composition > Component Library > Validation > Polish & Critique > Launch Readiness

```
Phase 0: GROUND     (2 steps)  "Know your problem"
Phase 1: DISCOVER   (5 steps)  "Know your market"
Phase 2: SHAPE      (4 steps)  "Explore your solution"
Phase 3: AUDIT      (5 steps)  "Find your problems"
Phase 4: BUILD      (5 steps)  "Ship your product"
Phase 5: VALIDATE   (4 steps)  "Prove it works"
Phase 6: LAUNCH     (5 steps)  "Ship and grow"

Total: 30 steps across 7 phases + 3 utility commands (/guide, /next, /status)
```

## Phase Shortcuts

| Shortcut | When to Use |
|----------|------------|
| Skip Phase 0 | Experienced designer with established process and clear problem definition |
| Skip Phase 1 | Adding to existing product with established direction and research |
| Skip Phase 2 | Existing product with established IA and visual direction |
| Partial Phase 3 | Quick check: just `/12-audit` (3.1) + `/14-access` (3.3) |
| Skip `/16-expose` (3.5) | No regulatory concerns, no AI features, single-market, single-device |
| Skip `/17-tokens` (4.1) | Token system already exists |
| Skip Phase 5 | Only if shipping an internal tool with no quality bar |
| Repeat Phase 5 | Loop `/23-roast` > `/24-remix` > `/19-ship` > `/23-roast` until quality bar met |
| Skip `/30-iterate` (6.5) | One-off project with no ongoing maintenance |

## Guide Protocol

1. **Determine where the user is**: Ask or infer which phase they're in.
   - **No UX experience / vibe coding / new to UX process** > Phase 0: GROUND — start with `/01-ground` (0.1)
   - **New project, no direction yet** > Phase 1: DISCOVER — start with `/03-research` (1.1)
   - **Have research, need to structure solution** > Phase 2: SHAPE — start with `/08-map` (2.1)
   - **Have a design or product to evaluate** > Phase 3: AUDIT — start with `/12-audit` (3.1)
   - **Know what to build, ready to code** > Phase 4: BUILD — start with `/17-tokens` (4.1)
   - **Built something, need to validate** > Phase 5: VALIDATE — start with `/22-test` (5.1)
   - **Ready to ship** > Phase 6: LAUNCH — start with `/26-verdict` (6.1)
   - **Not sure** > Start with Phase 0

   If the user provides context (e.g., "I'm building a fintech app" or "review this component"), infer the phase from context rather than asking.

   **Phase 4 readiness check**: When the user enters Phase 4 BUILD, check if any Phase 1 outputs exist (e.g., prior `/04-taste` or `/07-inspo` run). If none exist, recommend running `/04-taste` first — it takes ~5 minutes and significantly improves BUILD output quality. If the user wants to proceed without Phase 1, BUILD commands default to neutral/minimal style.

   **Phase 5 readiness check**: When the user enters Phase 5 VALIDATE, check that Phase 4 has produced buildable output. If not, recommend starting with `/17-tokens` (4.1) or `/19-ship` (4.3).

   **Phase 6 readiness check**: When the user enters Phase 6 LAUNCH, check that Phase 5 validation has passed. If not, recommend running `/23-roast` (5.2) first.

   **Phase 0 readiness check**: When the user has no defined problem statement or persona, recommend starting with `/01-ground` (0.1) or `/02-brief` (0.2). Phase 0 takes ~10 minutes and prevents hours of building the wrong thing.

2. **Show the phase map**: Display the 7-phase journey with the user's current position marked.

3. **Recommend the next command**: Based on the phase, suggest the specific next step with a one-line explanation.

4. **Show the phase checklist**: List all commands in the current phase as a numbered checklist.

5. **Suggest phase transitions**: When the user has completed enough of the current phase, proactively suggest moving to the next phase.

## Next Step
After running `/guide`, the user should:
- Run the first recommended command for their current phase
- Return to `/guide` at any time to reorient and check progress
- Use `/next` to auto-advance to the next step in the journey
- Use `/status` to see a progress dashboard of completed steps
- Use `/guide [phase]` to jump directly to a specific phase (e.g., `/guide ground`, `/guide build`)
