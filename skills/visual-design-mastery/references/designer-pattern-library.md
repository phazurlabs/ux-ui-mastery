# Designer Pattern Library

> 36+ world-class designers and design teams. Each entry: philosophy, 8 teachable pattern categories with specific, actionable techniques.

---

## Modernist Masters (Foundations)

### 1. Dieter Rams

**Era**: 1960s-1990s | **Known for**: Braun industrial design, 10 Principles of Good Design
**Philosophy**: "Less, but better." Design should be as little design as possible — back to purity, back to simplicity.

1. **Typography**: Used Helvetica and Akzidenz-Grotesk exclusively. Single weight for labels, bold only for critical callouts. All-caps at small sizes (10-11px equivalent) with generous letter-spacing (+0.08em). Never decorative.
2. **Color**: Restrained palette — white, black, warm gray (#E8E4DF), and one functional accent (Braun green #4A7C59 or orange #D4622B). Color is never decorative; it signals function. Background is always neutral.
3. **Spacing**: Generous, mathematical spacing. Consistent internal padding. Elements breathe. Minimum 24px between unrelated elements. Padding-to-content ratio favors padding.
4. **Composition**: Strict grid alignment. Asymmetric layouts with clear focal hierarchy. Controls grouped by function. Visual weight concentrated in one zone, balanced by whitespace.
5. **Motion**: No unnecessary animation. Transitions are functional (state changes only). If something moves, it communicates a change in state. Duration: 150-200ms max.
6. **Material/Surface**: Flat surfaces with subtle radius (2-4px). No gradients, no shadows unless indicating physical affordance. Material honesty — surfaces look like what they are.
7. **Iconography**: Geometric, mono-weight line icons. 24x24 grid. 1.5px stroke. Perfectly aligned to pixel grid. Every icon reducible to basic geometric shapes.
8. **Craft**: Obsessive alignment. Every element snaps to grid. No orphaned pixels. Controls feel engineered, not decorated. The invisible grid is the design.

### 2. Massimo Vignelli

**Era**: 1960s-2010s | **Known for**: NYC Subway map, American Airlines identity, Knoll graphics
**Philosophy**: "The life of a designer is a life of fight against the ugliness." Reduce to structure, use only a handful of typefaces, and let the grid do the work.

1. **Typography**: Limited to 6 typefaces for an entire career: Helvetica, Futura, Times New Roman, Garamond, Century, Bodoni. In UI: pick one sans-serif, one serif, done. Headings: Helvetica Bold, flush left. Body: 10-12pt, generous leading (1.5x). Never justified in narrow columns.
2. **Color**: Primary palette: black, white, red (#CC0000). Secondary: warm gray. That's it. Color is used for wayfinding and hierarchy, never decoration. Red = emphasis, action, or danger. Everything else is monochrome.
3. **Spacing**: Modular spacing based on the grid unit. If the column is 60px, spacing is 60px, 30px, or 15px — always derived from the grid. No arbitrary values. Margins equal or exceed gutters.
4. **Composition**: Strict column grid. Typically 3, 6, or 12 columns. Content never breaks the grid. Asymmetric layouts with text blocks anchored to grid intersections. Generous margins (minimum 5% of viewport width).
5. **Motion**: Vignelli predates digital motion, but the principle applies: transitions should be grid-aware. Elements slide along grid lines. No bouncing, no elastic effects.
6. **Material/Surface**: Completely flat. No shadows, no textures, no gradients. Surface = color field. Hierarchy through size and weight, not depth.
7. **Iconography**: Minimal. Preferred typographic solutions over icons. When icons are necessary: geometric, constructed from circles and rectangles, single stroke weight.
8. **Craft**: Absolute grid discipline. If you overlay a grid on any Vignelli design, every element aligns. Baseline grid for text. Mathematical relationships between all elements.

### 3. Josef Muller-Brockmann

**Era**: 1950s-1990s | **Known for**: Swiss Style, concert posters, Grid Systems in Graphic Design
**Philosophy**: "The grid system is an aid, not a guarantee." Mathematical precision creates objective visual communication.

1. **Typography**: Akzidenz-Grotesk and Helvetica. Flush left, ragged right — never centered, never justified. Strict size progression: 8, 11, 14, 20, 28, 40 (roughly 1.4x scale). Headings in medium weight, body in regular. No italics.
2. **Color**: Often monochrome or limited to 2-3 colors. When color is used: flat, unmodulated, high-saturation fields. Black text on white, or white text on colored field. No gradients. Colors chosen for maximum contrast.
3. **Spacing**: Derived entirely from the grid module. If the module is 20px, all spacing is multiples: 20, 40, 60, 80. Gutters are typically 1 module. Margins are 2-3 modules.
4. **Composition**: The grid IS the composition. Typically 4-column or 6-column. Strict horizontal zones. Images and text blocks occupy whole grid cells. Diagonal or angled elements used rarely but dramatically (concert posters).
5. **Motion**: N/A historically, but the principle: movement through rhythm. Repeated elements at regular intervals create implied motion. In UI: staggered list animations at consistent 50ms delays.
6. **Material/Surface**: Pure flat. Paper = surface. In UI: background-color only. No box-shadow, no border, no texture. Hierarchy through scale and position.
7. **Iconography**: Geometric constructions. Circles, lines, arcs. Mathematical precision. In UI: icons should be constructible with compass and ruler.
8. **Craft**: Mathematical relationships everywhere. The ratio between heading and body size matches the ratio between margin and gutter. Internal consistency is absolute.

### 4. Paul Rand

**Era**: 1950s-1990s | **Known for**: IBM, ABC, UPS logos, corporate identity systems
**Philosophy**: "Design is the silent ambassador of your brand." Playful geometry meets systematic thinking.

1. **Typography**: Preferred City Medium, Futura, and custom lettering. Mixed weights within a composition for visual play. Uppercase for logos, mixed case for body. Generous letter-spacing in headings (+0.05em).
2. **Color**: Bold, primary colors (IBM blue #0066CC, UPS brown #644117). Limited palette but used with confidence. Flat color fields as compositional elements. Color blocks as backgrounds, not just accents.
3. **Spacing**: Playful but structured. Elements have room to breathe. Overlap used deliberately for visual interest. Generous margins frame the composition.
4. **Composition**: Asymmetric with playful balance. Geometric shapes (circles, squares, triangles) as compositional elements alongside type. Collage-like layering. Strong focal point with supporting elements.
5. **Motion**: Implied motion through arrangement. Diagonal placement, overlapping shapes. In UI: subtle rotation (1-3deg) on interactive elements.
6. **Material/Surface**: Flat color fields. Occasional paper texture. In UI: bold background colors for sections, not subtle grays.
7. **Iconography**: Rebus-style (picture + letter combinations). Geometric, playful, memorable. IBM's striped logo: 8 horizontal bars. In UI: icons can have personality while remaining clear.
8. **Craft**: Every element serves a dual purpose — functional and delightful. The IBM "Eye-Bee-M" poster: communication through play. In UI: loading states, empty states, and errors as craft opportunities.

### 5. Jan Tschichold

**Era**: 1920s-1970s | **Known for**: Die neue Typographie, Penguin book covers, asymmetric typography
**Philosophy**: "Perfect typography is more a science than an art." Typography is the foundation of all visual design.

1. **Typography**: Flush left, ragged right as default. Sans-serif for modern communication, serif for classical. Strict hierarchy through size, weight, and position — never through decoration. Optimal line length: 50-60 characters. Line-height: 120-145% of font size.
2. **Color**: Minimal. Black and red as the typographic color system. Red for emphasis only. In UI: a single accent color, used only for primary actions and critical information.
3. **Spacing**: Optically even spacing over mathematically even. Kerning adjusted by eye, not by metrics. In UI: use optical alignment — a circle needs to be slightly larger than a square to appear the same size.
4. **Composition**: Asymmetric balance. Title block anchored top-left, body text below. Clear reading path from top-left to bottom-right. Nothing centered unless the entire composition is centered.
5. **Motion**: N/A historically. Principle: movement follows reading direction. Left-to-right, top-to-bottom. Animations should follow natural reading flow.
6. **Material/Surface**: Paper as the material. In UI: let the content surface be neutral. No competing textures or patterns behind text.
7. **Iconography**: Preferred typographic symbols (arrows, bullets, rules) over pictorial icons. In UI: sometimes a well-set label is better than an icon.
8. **Craft**: The spacing between letters is as important as the letters themselves. In UI: letter-spacing, line-height, and paragraph spacing are as critical as font choice.

## Digital Pioneers

### 6. Susan Kare

**Era**: 1980s-present | **Known for**: Original Macintosh icons, Chicago font, card solitaire
**Philosophy**: "Good icons should be more like road signs than illustrations." Clarity at the smallest size.

1. **Typography**: Designed Chicago (Mac system font) — optimized for 72dpi bitmap rendering. In UI: always test type at the smallest size it will appear. If it's not clear at 12px, redesign.
2. **Color**: Originally 1-bit (black and white). Constraint breeds clarity. In UI: if an icon doesn't work in monochrome, it won't work in color. Design mono-first, add color second.
3. **Spacing**: Pixel-grid precision. Every pixel counts at small sizes. In UI: icons at 16x16 must be pixel-perfect. No anti-aliased ambiguity at small sizes.
4. **Composition**: Small canvas, maximum meaning. 32x32 pixel grid = every pixel is a design decision. In UI: constraints force better design. Work within the grid.
5. **Motion**: Static icons that imply action through pose. The Mac "watch" cursor = time passing. In UI: an icon's static state should communicate its purpose without animation.
6. **Material/Surface**: Flat bitmap. No gradients, no shadows (at original scale). In UI: icons at small sizes (16-20px) should be flat and crisp, not rendered with effects.
7. **Iconography**: Metaphor-based: trash can = delete, floppy disk = save, magnifying glass = search. Universal metaphors that transcend language. Test: can a 5-year-old guess the meaning?
8. **Craft**: Pixel-level attention. Every pixel toggled on or off deliberately. In UI: zoom to 800% on every icon and check that each pixel is intentional.

### 7. Bill Moggridge

**Era**: 1970s-2012 | **Known for**: First laptop (GRiD Compass), IDEO co-founder, interaction design discipline
**Philosophy**: "Designing interactions means designing for people." The interface disappears when the interaction is right.

1. **Typography**: Functional, not stylistic. Type serves the interaction, not the aesthetic. In UI: body text should be invisible — if the user notices the font, it's wrong.
2. **Color**: Color as feedback. Green = success, red = error, blue = interactive, gray = disabled. In UI: color coding should be learnable and consistent throughout the product.
3. **Spacing**: Touch target sizing: minimum 44x44px (Apple HIG). Spacing between interactive elements: minimum 8px to prevent mis-taps. In UI: spacing is an interaction design decision, not just visual.
4. **Composition**: Task-oriented layout. Group by workflow, not by data type. In UI: the layout should match the user's mental model of the task.
5. **Motion**: Feedback-driven. Every action gets a visible response within 100ms. In UI: button press → immediate visual feedback (scale, color change) before the action completes.
6. **Material/Surface**: Affordance-driven. Buttons look pressable, sliders look draggable, text fields look editable. In UI: interactive elements must be visually distinct from static content.
7. **Iconography**: Action-oriented. Icons represent verbs (edit, delete, share), not nouns. In UI: toolbar icons should depict what happens when you click.
8. **Craft**: Prototype obsessively. The design isn't done until it feels right in hand. In UI: test on real devices. A design that looks perfect in Figma may feel wrong on a phone.

### 8. John Maeda

**Era**: 1990s-present | **Known for**: Laws of Simplicity, MIT Media Lab, Design in Tech Reports
**Philosophy**: "Simplicity is about subtracting the obvious and adding the meaningful." Computation + design = new possibilities.

1. **Typography**: Code-influenced typography. Monospace as a design choice, not just for code. In UI: mixing mono and sans in data-heavy interfaces creates natural hierarchy (labels in sans, values in mono).
2. **Color**: Computational color. Algorithmically generated palettes. In UI: use oklch() to generate harmonious palettes programmatically rather than picking colors by hand.
3. **Spacing**: "SHE" — Shrink, Hide, Embody. Reduce spacing when complexity grows. In UI: progressive disclosure with tighter spacing on detail views, generous spacing on overview.
4. **Composition**: Layered complexity. Simple surface, depth on demand. In UI: the default view should be radically simple; complexity is opt-in.
5. **Motion**: Meaningful transitions between simplicity levels. Expanding/collapsing reveals information architecture. In UI: use expand/collapse animations (200-300ms, ease-out) to show progressive disclosure.
6. **Material/Surface**: Digital-native surfaces. Not skeuomorphic, not flat — responsive surfaces that react to input. In UI: hover states, focus rings, and active states as surface behaviors.
7. **Iconography**: Minimal, sometimes replaced by text. "When in doubt, label it." In UI: icon + label is almost always better than icon alone.
8. **Craft**: The 10th Law of Simplicity: "Simplicity is about subtracting the obvious and adding the meaningful." In UI: every element must justify its existence. If removing it doesn't hurt, remove it.

## Apple / Hardware Design

### 9. Jony Ive

**Era**: 1996-2019 | **Known for**: iMac, iPod, iPhone, iOS 7 redesign
**Philosophy**: "True simplicity is derived from so much more than just the absence of clutter." Material honesty and inevitable form.

1. **Typography**: San Francisco (SF Pro) — designed for Apple's ecosystem. Display variant for >=20pt, Text variant for <20pt. Tight heading tracking (-0.02em), comfortable body tracking (0). Weight: Regular for body, Semibold for emphasis, Bold sparingly.
2. **Color**: Restrained system colors. iOS palette: blue (#007AFF) for interactive, red (#FF3B30) for destructive, green (#34C759) for positive. Backgrounds: pure white (#FFFFFF) or system gray (#F2F2F7). Vibrancy and translucency as material effects.
3. **Spacing**: 8pt grid system. Standard margins: 16pt (compact), 20pt (regular). Section spacing: 32pt. Content insets: 16pt. Consistent padding inside components: 12pt vertical, 16pt horizontal.
4. **Composition**: Edge-to-edge content. Full-bleed images. Navigation at top or bottom, never competing with content. Content is the interface. Generous top margins on scroll views.
5. **Motion**: Physics-based: spring animations (damping: 0.7-0.85, response: 0.3-0.5s). Gesture-driven: swipe, pinch, rotate map directly to visual change. No arbitrary easing — everything feels physical.
6. **Material/Surface**: Translucent materials (UIBlurEffect). Layered depth: background → secondary → primary → overlay. Subtle shadows for elevation (0 2px 8px rgba(0,0,0,0.08)). Border-radius: 10-13px for cards, 20-22px for sheets.
7. **Iconography**: SF Symbols: 5,000+ icons with 9 weights and 3 scales. Hierarchical rendering (primary, secondary, tertiary layers). In UI: use weight-matched icons that correspond to the adjacent text weight.
8. **Craft**: Sub-pixel rendering. Retina-optimized assets. Every pixel justified. The home indicator is exactly 5px tall, 134px wide, with 4px border-radius. That level of precision.

### 10. Alan Dye

**Era**: 2010s-present | **Known for**: Apple VP of Human Interface Design, watchOS, SF Pro evolution
**Philosophy**: Extending Apple's design language across contexts — from 38mm watch to 27" display — while maintaining craft quality.

1. **Typography**: SF Pro with optical sizing. Compact variant for watchOS. Rounded variant for playful contexts (Fitness). Dynamic Type with 11 text styles that scale with user preference. In UI: always support Dynamic Type / text scaling.
2. **Color**: watchOS complications: vivid colors on black OLED (#55BEF0 blue, #FC6264 red, #67CD67 green). High chroma, high lightness on pure black. In UI: dark mode colors should be vibrant on dark, not washed out.
3. **Spacing**: watchOS: 2px grid (half the iOS 4px minimum). Extreme density without sacrificing legibility. In UI: small screens need smaller grids but maintained touch targets.
4. **Composition**: Circular layouts for watchOS. Vertical scrolling as primary navigation. Focus + Context: one primary element fills the viewport, supporting elements above/below. In UI: prioritize ruthlessly on small screens.
5. **Motion**: Digital Crown haptics synchronized with visual scrolling. In UI: haptic feedback (where available) reinforces visual state changes. Taptic-style micro-interactions.
6. **Material/Surface**: OLED-optimized: true black (#000000) backgrounds save power and create infinite contrast. In UI: on OLED devices, use true black, not dark gray.
7. **Iconography**: SF Symbols scaled for watchOS (small optical size). Monochrome at small sizes, multicolor at larger sizes. In UI: icon rendering should adapt to display size.
8. **Craft**: Complications display 4-7 data points in 20mm of space while remaining legible. In UI: data density is a design skill — show more with less, never by making things smaller.

### 11. Mike Matas

**Era**: 2000s-present | **Known for**: Push Pop Press (interactive books), Paper by FiftyThree, early Apple UI design
**Philosophy**: "The best interfaces feel like direct manipulation of real objects." Physics and gesture create delight.

1. **Typography**: Clean sans-serif at large sizes for headers, comfortable serif for long-form reading. In UI: different type treatments for different content modes (scanning vs. reading).
2. **Color**: Warm, paper-like backgrounds (#FAF8F5). Ink-like text (#1A1A1A, not pure black). Accent colors inspired by art supplies. In UI: slightly warm neutrals feel more natural than cold grays.
3. **Spacing**: Content-aware spacing. Text gets generous margins (60-80px). Interactive elements get tight, responsive spacing. In UI: spacing should reflect content type, not be uniform.
4. **Composition**: Full-screen immersive content. Parallax layers. Content breaks out of traditional boxes. In UI: hero content should dominate the viewport.
5. **Motion**: Rubber-banding, momentum scrolling, velocity-based animations. Flick to dismiss, pinch to zoom. Duration follows gesture velocity. In UI: spring animations with velocity inheritance.
6. **Material/Surface**: Paper-like textures, canvas feel. Subtle grain. In UI: background-image with noise texture (opacity: 0.02-0.04) adds organic warmth.
7. **Iconography**: Minimal, often replaced by gestural affordances. The content IS the interface. In UI: reduce chrome, increase content.
8. **Craft**: Gesture-to-animation mapping. Drag threshold, velocity tracking, rubber-band physics. In UI: interactive prototypes that feel physical require tuning spring constants (stiffness: 200-400, damping: 20-30).

## Product Design Leaders

### 12. Rasmus Andersson

**Era**: 2010s-present | **Known for**: Inter typeface, Figma early design, Spotify design, Linear visual language
**Philosophy**: "Design is problem-solving with constraints." Functional beauty through systematic restraint.

1. **Typography**: Designed Inter — the UI typeface. Optimized for screen rendering at small sizes (11-16px). Features: tabular numbers, slashed zero, contextual alternates. In UI: Inter at 400 (body), 500 (labels), 600 (headings). -0.011em tracking at 14px. line-height: 1.5 for body.
2. **Color**: Monochrome-first. Linear uses near-black backgrounds (#1A1A2E), white text, and a single accent color per context. In UI: start with monochrome, add one accent. If the design works in grayscale, it works in color.
3. **Spacing**: 4px base unit. Tight but precise. Component padding: 8px 12px (small), 10px 16px (medium), 12px 20px (large). Section spacing: 24px, 32px, 48px.
4. **Composition**: Dense, keyboard-first interfaces. Command palette as primary navigation (Cmd+K). Content-to-chrome ratio heavily favors content. In UI: minimize UI chrome, maximize content area.
5. **Motion**: Minimal, fast. 100-150ms transitions. Linear easing or slight ease-out. No spring animations. No overshoot. In UI: speed > delight for productivity tools.
6. **Material/Surface**: Flat with subtle borders (1px, rgba(255,255,255,0.06) on dark). No shadows on dark UI. Hover states: background-color change (rgba(255,255,255,0.04)). In UI: on dark backgrounds, use border or subtle background shift for elevation.
7. **Iconography**: 16x16, 1.5px stroke, rounded caps and joins. Monochrome. Pixel-snapped. In UI: icons should be optically balanced at their most common display size.
8. **Craft**: Keyboard shortcuts for everything. No action requires more than 2 clicks. In UI: the visual hierarchy should match the keyboard navigation order.

### 13. Tobias van Schneider

**Era**: 2010s-present | **Known for**: Spotify design lead, Semplice portfolio CMS, bold experimentation
**Philosophy**: "Break rules intentionally, not accidentally." Experimental within systematic constraints.

1. **Typography**: Bold type choices. Extra-bold weights (800-900) for headlines. Custom or distinctive typefaces. In UI: one bold typeface choice can define the entire product personality.
2. **Color**: Saturated, unexpected palettes. Spotify's green (#1DB954) was bold for its era. Duotone effects. In UI: one unexpected color choice at high saturation creates instant memorability.
3. **Spacing**: Generous hero sections (80vh+). Tight body content. The contrast between spacious and dense creates rhythm. In UI: alternate between breathing room and density.
4. **Composition**: Full-bleed imagery. Overlapping elements. Text over images with gradient overlays (linear-gradient(180deg, transparent 0%, rgba(0,0,0,0.7) 100%)). In UI: confident overlap creates depth.
5. **Motion**: Bold entrance animations. Elements animate in with personality (scale from 0.8 to 1, fade, slight rotation). In UI: entrance animations should match the brand energy — conservative for banking, bold for creative.
6. **Material/Surface**: Dark mode by default. Rich textures, gradients. In UI: dark backgrounds with vibrant accent colors create premium feeling.
7. **Iconography**: Custom icon sets with personality. Slightly thicker stroke (2px). Rounded, friendly geometry. In UI: icon style is a brand differentiator.
8. **Craft**: Surprise in details. Custom cursor, unusual hover effects, unexpected micro-interactions. In UI: craft one signature interaction that users remember.

### 14. Julie Zhuo

**Era**: 2010s-present | **Known for**: Facebook/Meta VP of Product Design, "The Making of a Manager"
**Philosophy**: "Good design is invisible. Bad design is everywhere." Systems thinking at scale.

1. **Typography**: System fonts for performance (San Francisco, Roboto, Segoe). Strict 4-level hierarchy: title, subtitle, body, caption. In UI: more than 4 type levels in a single view creates confusion.
2. **Color**: Blue as primary (#1877F2 — Facebook blue). Semantic colors for states. Neutral gray scale for content hierarchy. In UI: at scale, color must be systematic, not artistic.
3. **Spacing**: Consistent 8px grid. Component library with fixed spacing tokens: xs(4), sm(8), md(16), lg(24), xl(32). In UI: named spacing tokens prevent drift across teams.
4. **Composition**: Feed-based layouts. Card patterns. Consistent component reuse. In UI: at scale, composition = component composition. The system IS the design.
5. **Motion**: Restrained. Meaningful transitions (page changes, modal reveals). 200ms standard duration. In UI: motion that doesn't aid understanding is motion that distracts.
6. **Material/Surface**: Cards with subtle shadow (0 1px 2px rgba(0,0,0,0.1)). White surfaces. Light dividers (1px, #E4E6EB). In UI: elevation through shadow should be minimal and consistent.
7. **Iconography**: Outlined icons for inactive, filled for active (tab bar pattern). 24px standard size. In UI: icon states (active/inactive) should have clear visual distinction.
8. **Craft**: Accessibility at scale. Focus management, screen reader support, color contrast enforcement. In UI: craft at scale means automated quality checks, not manual polish.

### 15. Luke Wroblewski

**Era**: 2000s-present | **Known for**: Mobile First, Web Form Design, input innovation
**Philosophy**: "Mobile first isn't just about screen size — it's about focus." Constraints drive better design.

1. **Typography**: Large touch-friendly type. Minimum 16px body on mobile (prevents iOS zoom). Input labels: 14px above, not beside. In UI: form labels above inputs, always, on mobile.
2. **Color**: High contrast inputs. Focus state: 2px border in primary color. Error: red border + red text + icon. In UI: form field states need 3+ visual signals (not just color).
3. **Spacing**: Touch targets: 48px minimum height. Spacing between form fields: 24px. Group related fields with 8px gap, separate groups with 32px. In UI: form spacing is not uniform — it communicates grouping.
4. **Composition**: Single-column forms on mobile. Progressive disclosure: show fields as needed. In UI: long forms should be multi-step, not multi-scroll.
5. **Motion**: Inline validation timing: validate on blur, not on keystroke. Success animation on form submission (checkmark, 400ms). In UI: validation timing affects perceived usability more than validation accuracy.
6. **Material/Surface**: Input fields: clear boundaries (1px border, #D1D5DB), adequate height (44-48px), inner padding (12px 16px). In UI: text inputs should look like text inputs — clear, bordered, properly sized.
7. **Iconography**: Input adornments: icons inside fields (search magnifier, password eye toggle). Position: 12px from edge. Size: 20px. In UI: input icons clarify purpose but must not reduce usable text area.
8. **Craft**: Keyboard optimization: correct input types (email, tel, url), autocomplete attributes, autofocus on first field. In UI: the right virtual keyboard for each field is a craft detail.

### 16. Claudio Guglieri

**Era**: 2010s-present | **Known for**: Microsoft Design, large-scale design systems, Fluent Design
**Philosophy**: "Design systems are living products, not static libraries." Scalable design for global products.

1. **Typography**: Segoe UI for Windows, system fonts for cross-platform. Type ramp with clear purpose: each size has a named role. In UI: every font-size in the system should map to a semantic name.
2. **Color**: Fluent Design color system: shared hues across light/dark, adjusted for contrast. In UI: don't just swap colors for dark mode — each color needs a dark-mode-specific value with adequate contrast.
3. **Spacing**: Fluent density: compact (32px row height), normal (40px), spacious (48px). In UI: density is a user preference, not a design decision — support multiple densities.
4. **Composition**: Responsive containers, not responsive pages. Each component owns its responsive behavior. In UI: container queries > media queries for component-based design.
5. **Motion**: Fluent motion: shared choreography language. Enter/exit (fade + translate 20px), expand/collapse, drill-in. Duration: 150ms (micro), 300ms (page). In UI: motion tokens standardize animation across a system.
6. **Material/Surface**: Acrylic (translucent blur), Mica (wallpaper tinting), layered elevation. In UI: material effects should serve hierarchy (which layer am I on?), not decoration.
7. **Iconography**: Fluent icons: variable weight (regular/filled), 16/20/24/28/32/48px sizes. In UI: an icon system needs size-specific optical adjustments, not just scaling.
8. **Craft**: Themeable design systems. Every visual property is a token. In UI: if you can't theme it, it's not systematic.

8. **Craft**: Interactive code examples. API responses that animate. In UI: documentation that responds to user input is the highest form of developer experience design.

## Interaction & Motion Specialists

### 30. Pasquale D'Silva

**Known for**: Motion design principles for UI, "Transitional Interfaces"
**Philosophy**: "Animation is the connective tissue of interface design." Motion communicates causality.

1. **Typography**: Type participates in motion — text elements animate with content, not independently. In UI: when a heading changes, crossfade the text (150ms) rather than instant-swapping.
2. **Color**: Color as transition signal. Background color changes indicate state change. In UI: container background-color transition (200ms ease) communicates context shift.
3. **Spacing**: Spatial animation: elements move FROM where they came FROM and TO where they're going. In UI: a new detail view should slide in from the direction of the list item that triggered it.
4. **Composition**: Choreographed sequences. Related elements animate together, in staggered order. In UI: list items enter with 30ms stagger, starting from the first visible item.
5. **Motion**: The primary discipline. Rules: (1) Everything that changes should animate. (2) Animation should indicate causality. (3) Duration: 150-300ms for UI, 300-500ms for page transitions. (4) Easing: ease-out for entering, ease-in for exiting.
6. **Material/Surface**: Surfaces respond to interaction: press = scale down (0.97), release = spring back. In UI: active states should feel physical.
7. **Iconography**: Animated icon transitions (hamburger → X, play → pause). In UI: icon morphing communicates state change better than icon replacement.
8. **Craft**: Motion prototyping in code, not in After Effects. In UI: motion specified as CSS/JS values, not video references.

### 31. Issara Willenskomer

**Known for**: "UX in Motion Manifesto," 12 Principles of UX in Motion
**Philosophy**: "Motion is the next frontier of usability." Motion supports usability, not just aesthetics.

1. **Typography**: Text as motion participant. Hierarchy changes animated. In UI: when text importance changes (e.g., selected tab label), animate the weight/size transition.
2. **Color**: Color transitions signal semantic change. In UI: status color transitions (yellow→green for "saving"→"saved") should be smooth (300ms).
3. **Spacing**: Spatial relationships maintained through motion. When A moves, B moves in response. In UI: connected elements should animate together (parent-child motion).
4. **Composition**: 12 principles include: easing, offset & delay, parenting, transformation, value change, masking, overlay, cloning, parallax, dimensionality, dolly/zoom, obscuration.
5. **Motion**: Offset & delay: stagger related elements by 25-50ms. Parenting: child elements inherit parent motion. Transformation: shape-morph communicates function change. In UI: implement at least 3 of the 12 principles for a polished product.
6. **Material/Surface**: Obscuration: blur/dim background when overlay appears (backdrop-filter: blur(8px), background: rgba(0,0,0,0.4)).
7. **Iconography**: Transformation principle: icon shapes morph between states using SVG path interpolation.
8. **Craft**: Motion audit: catalog every state change in the product and determine if motion would aid understanding.

## How to Use This Library

1. **Direction Setting**: "Make it feel like a [Designer] product" — reference that designer's 8 pattern categories to generate specific recommendations.
2. **Decision Justification**: "We should use Inter at 500 for labels because Rasmus Andersson designed Inter specifically for this use case, and Linear's implementation validates it at scale."
3. **Pattern Mixing**: Combine patterns from different designers — e.g., Vignelli's grid discipline + Stripe's gradient craft + Linear's density.
4. **Anti-Pattern Detection**: If a UI violates patterns from ALL listed designers, it's almost certainly a problem.
5. **Sector Matching**: Map sector norms to designer archetypes — e.g., fintech → Rams (trust, reduction), social → Walsh (energy, color), dev tools → Andersson (density, speed).
