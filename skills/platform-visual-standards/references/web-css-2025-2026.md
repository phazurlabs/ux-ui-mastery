# Modern Web CSS 2025-2026 Design Standards

## The CSS Renaissance

The period from 2023-2026 represents the most significant expansion of CSS capabilities since CSS3. Features that previously required JavaScript, preprocessors, or complex workarounds are now native CSS. This reference covers every major capability a modern web designer should use, and the outdated patterns they replace.

---

## Container Queries (@container)

### What They Solve

Media queries respond to the viewport. Container queries respond to the size of a component's parent container. This enables true component-based responsive design — a card component adapts its layout whether it lives in a narrow sidebar or a wide main content area, without knowing where it's placed.

### Syntax

```css
/* Define a container */
.card-wrapper {
    container-type: inline-size;
    container-name: card;
}

/* Query the container */
@container card (min-width: 400px) {
    .card {
        grid-template-columns: 200px 1fr;
        gap: 1.5rem;
    }
}

@container card (min-width: 700px) {
    .card {
        grid-template-columns: 300px 1fr;
        gap: 2rem;
    }
    .card__title {
        font-size: 1.5rem;
    }
}
```

### Container Types

- `container-type: inline-size` — query the inline (width) dimension only. Most common.
- `container-type: size` — query both inline and block dimensions. Use when height matters.
- `container-type: normal` — default, no containment (cannot be queried).

### Container Query Units

| Unit | Meaning |
|------|---------|
| `cqi` | 1% of container's inline size (width in horizontal writing) |
| `cqb` | 1% of container's block size (height) |
| `cqw` | 1% of container's width |
| `cqh` | 1% of container's height |
| `cqmin` | Smaller of cqi or cqb |
| `cqmax` | Larger of cqi or cqb |

```css
/* Fluid typography based on container width */
.card__title {
    font-size: clamp(1rem, 3cqi, 2rem);
}
```

### Named Containers

```css
.sidebar { container-name: sidebar; container-type: inline-size; }
.main    { container-name: main;    container-type: inline-size; }

@container sidebar (max-width: 250px) {
    .nav-label { display: none; }  /* Only affects sidebar context */
}
```

### Browser Support

All modern browsers (Chrome 105+, Safari 16+, Firefox 110+). Safe for production in 2025.

## View Transitions API

### What It Solves

Smooth animated transitions between page states (SPA) or entire page navigations (MPA) without complex animation libraries. The browser snapshots old and new states and crossfades between them.

### Single-Page Application (SPA)

```javascript
// Wrap a DOM update in a view transition
document.startViewTransition(() => {
    // Update the DOM — swap content, change route, etc.
    updateContent();
});
```

The browser automatically creates `::view-transition-old(root)` and `::view-transition-new(root)` pseudo-elements and crossfades between them.

### Custom Transition Styles

```css
/* Default crossfade duration */
::view-transition-old(root),
::view-transition-new(root) {
    animation-duration: 300ms;
}

/* Slide transition */
::view-transition-old(root) {
    animation: slide-out 300ms ease-in both;
}
::view-transition-new(root) {
    animation: slide-in 300ms ease-out both;
}

@keyframes slide-out {
    to { transform: translateX(-100%); }
}
@keyframes slide-in {
    from { transform: translateX(100%); }
}
```

### Per-Element Transitions

```css
/* Name specific elements for independent transitions */
.hero-image {
    view-transition-name: hero;
}

.page-title {
    view-transition-name: title;
}

/* Each named element gets its own transition pair */
::view-transition-old(hero) {
    animation: fade-out 200ms ease;
}
::view-transition-new(hero) {
    animation: fade-in 300ms ease;
}
```

### Multi-Page Application (MPA) Cross-Document Transitions

```css
/* Enable on both the source and destination pages */
@view-transition {
    navigation: auto;
}

/* Same view-transition-name on matching elements across pages */
.product-card { view-transition-name: product-hero; }
/* On detail page: */
.product-hero { view-transition-name: product-hero; }
```

### Browser Support

Chrome 111+, Safari 18+, Firefox 126+. Progressive enhancement — transitions gracefully degrade to instant swaps.

## Scroll-Driven Animations

### What They Solve

Animations that progress based on scroll position rather than time. Previously required Intersection Observer + JavaScript calculations. Now pure CSS, running on the compositor thread for smooth 60fps performance.

### Scroll Progress Timeline

```css
/* Animation tied to scroll position of a container */
.progress-bar {
    animation: grow-width linear;
    animation-timeline: scroll();  /* Defaults to nearest scroll ancestor */
}

@keyframes grow-width {
    from { width: 0%; }
    to   { width: 100%; }
}
```

### View Progress Timeline

```css
/* Animation tied to an element entering/leaving the viewport */
.card {
    animation: fade-slide-in linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 100%;  /* Animate during entry */
}

@keyframes fade-slide-in {
    from {
        opacity: 0;
        transform: translateY(50px);
    }
    to {
        opacity: 1;
        transform: translateY(0);
    }
}
```

### Animation Range

```css
/* Control which portion of scroll drives the animation */
animation-range: entry 0% entry 100%;     /* Only during entry into view */
animation-range: exit 0% exit 100%;       /* Only during exit from view */
animation-range: contain 0% contain 100%; /* While fully contained in view */
animation-range: cover 0% cover 100%;     /* From first pixel visible to last pixel gone */
```

### Use Cases

- **Reading progress bar**: `animation-timeline: scroll(root)` on a fixed bar
- **Parallax backgrounds**: slower scroll rate via keyframe transform
- **Reveal animations**: fade/slide elements as they enter viewport
- **Sticky header transforms**: shrink header as user scrolls down
- **Horizontal scroll galleries**: progress indicator for horizontal scrollers

### Browser Support

Chrome 115+, Safari 18.4+ (partial), Firefox 2025+. Use `@supports (animation-timeline: scroll())` for progressive enhancement.

## oklch() Color Function

### Why oklch() Over hsl() or rgb()

- **Perceptually uniform**: equal numeric changes produce equal perceived changes (unlike HSL where yellow 50% looks far lighter than blue 50%)
- **Wide gamut**: can express colors beyond sRGB, reaching P3 and Rec.2020 displays
- **Predictable palettes**: keep lightness constant, vary hue — all results look equally light
- **Accessible by math**: a lightness difference of 0.40+ between text and background reliably meets WCAG AA

### Syntax

```css
/* oklch(lightness chroma hue / alpha) */
color: oklch(0.70 0.15 250);         /* A vivid blue */
color: oklch(0.70 0.15 250 / 0.5);   /* 50% transparent */

/* Lightness: 0 (black) to 1 (white) */
/* Chroma: 0 (gray) to ~0.37 (max vividness, varies by hue) */
/* Hue: 0-360 degrees */
```

### Generating Consistent Palettes

```css
:root {
    /* Brand blue at 5 lightness steps — all equally vivid */
    --blue-100: oklch(0.95 0.05 250);
    --blue-300: oklch(0.80 0.10 250);
    --blue-500: oklch(0.65 0.15 250);
    --blue-700: oklch(0.45 0.12 250);
    --blue-900: oklch(0.25 0.08 250);
}
```

### Relative Color Syntax

```css
/* Derive colors from a base */
:root {
    --brand: oklch(0.65 0.20 145);

    /* Lighter variant */
    --brand-light: oklch(from var(--brand) calc(l + 0.2) c h);

    /* Darker variant */
    --brand-dark: oklch(from var(--brand) calc(l - 0.2) c h);

    /* Desaturated variant */
    --brand-muted: oklch(from var(--brand) l calc(c * 0.3) h);

    /* Complementary color */
    --brand-complement: oklch(from var(--brand) l c calc(h + 180));
}
```

### Wide Gamut Colors

```css
/* P3 color that's more vivid than sRGB can display */
.vibrant-button {
    background: oklch(0.65 0.29 145);  /* Vivid green — uses P3 gamut */
}

/* Fallback for non-P3 displays handled automatically — browser clamps to sRGB */
```

### Browser Support

All modern browsers (Chrome 111+, Safari 15.4+, Firefox 113+). Safe for production.

## Anchor Positioning

### What It Solves

Position elements relative to other elements without JavaScript. Tooltips, popovers, dropdowns, and floating labels that automatically track their anchor element and reposition on overflow.

### Syntax

```css
/* Define the anchor */
.trigger {
    anchor-name: --trigger;
}

/* Position relative to the anchor */
.tooltip {
    position: fixed;
    position-anchor: --trigger;

    /* Place below the anchor, centered horizontally */
    top: anchor(bottom);
    left: anchor(center);
    translate: -50% 8px;  /* Center and add gap */
}
```

### Fallback Positioning

```css
/* Try bottom first, fall back to top if it overflows */
.tooltip {
    position: fixed;
    position-anchor: --trigger;
    top: anchor(bottom);
    left: anchor(center);

    position-try-fallbacks: flip-block;  /* Flip to top if bottom overflows */
}

/* Custom fallback positions */
@position-try --above {
    bottom: anchor(top);
    top: auto;
}

.tooltip {
    position-try-fallbacks: --above;
}
```

### Use Cases

- Tooltips that track buttons
- Dropdown menus aligned to triggers
- Floating labels for form fields
- Popovers with smart repositioning
- Tour/onboarding highlights

### Browser Support

Chrome 125+, Safari 18.4+ (partial), Firefox 2025+. Progressive enhancement recommended.

## CSS Nesting

### What It Solves

Native CSS nesting eliminates the need for Sass/Less/PostCSS nesting. Write nested selectors directly in CSS.

### Syntax

```css
.card {
    padding: 1.5rem;
    border-radius: 12px;

    & .title {
        font-size: 1.25rem;
        font-weight: 600;
    }

    & .body {
        color: oklch(0.40 0 0);
        line-height: 1.6;
    }

    &:hover {
        box-shadow: 0 4px 12px oklch(0 0 0 / 0.1);
    }

    /* Media queries nest inside rules */
    @media (min-width: 768px) {
        padding: 2rem;
    }

    /* Container queries nest too */
    @container (min-width: 400px) {
        display: grid;
        grid-template-columns: 200px 1fr;
    }
}
```

### Browser Support

All modern browsers (Chrome 120+, Safari 17.2+, Firefox 117+). Safe for production.

## :has() Selector

### What It Solves

The "parent selector" CSS never had. Select elements based on their descendants, subsequent siblings, or internal state.

### Patterns

```css
/* Card with an image gets different aspect ratio */
.card:has(img) {
    aspect-ratio: 16 / 9;
}

/* Card WITHOUT an image */
.card:not(:has(img)) {
    padding: 2rem;
}

/* Form field container turns red when input is invalid */
.field:has(input:invalid) {
    border-color: oklch(0.55 0.25 25);
}

/* Grid adapts column count based on number of children */
.grid:has(> :nth-child(4)) {
    grid-template-columns: repeat(2, 1fr);
}
.grid:has(> :nth-child(7)) {
    grid-template-columns: repeat(3, 1fr);
}

/* Style body when a modal is open */
body:has(.modal[open]) {
    overflow: hidden;
}

/* Style a label when its associated checkbox is checked */
label:has(input:checked) {
    background: oklch(0.90 0.05 250);
}
```

### Browser Support

All modern browsers (Chrome 105+, Safari 15.4+, Firefox 121+). Safe for production.

## Subgrid

### What It Solves

Child grids inherit track sizing from parent grids. Cards in a grid can align their internal elements (titles, descriptions, buttons) across cards, even when content varies in length.

### Syntax

```css
.card-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 1.5rem;
}

.card {
    display: grid;
    grid-template-rows: subgrid;  /* Inherit parent's row tracks */
    grid-row: span 3;            /* Card spans 3 implicit rows */
}
```

### Use Case: Aligned Card Content

```css
/* Parent grid */
.products {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
    grid-template-rows: auto;  /* Rows will be defined by subgrid children */
    gap: 1.5rem;
}

/* Each product card aligns title, description, and price across all cards */
.product-card {
    display: grid;
    grid-row: span 4;            /* image + title + description + price */
    grid-template-rows: subgrid;
}
```

### Browser Support

All modern browsers (Chrome 117+, Safari 16+, Firefox 71+). Safe for production.

## @layer Cascade Layers

### What They Solve

Control the cascade order without specificity wars. Third-party CSS, resets, and utility classes coexist without `!important` hacks.

### Syntax

```css
/* Declare layer order (first = lowest priority) */
@layer reset, base, components, utilities;

/* Reset layer — lowest priority */
@layer reset {
    * { margin: 0; padding: 0; box-sizing: border-box; }
}

/* Base layer */
@layer base {
    body { font-family: system-ui; line-height: 1.6; }
}

/* Components layer */
@layer components {
    .button { padding: 0.75rem 1.5rem; border-radius: 8px; }
}

/* Utilities layer — highest priority */
@layer utilities {
    .mt-4 { margin-top: 1rem; }
    .hidden { display: none; }
}

/* Import third-party CSS into a low-priority layer */
@import "framework.css" layer(framework);
```

### Key Behavior

- Unlayered styles always beat layered styles (regardless of specificity)
- Within a layer, normal specificity rules apply
- `!important` reverses layer order (first layer wins)

### Browser Support

All modern browsers (Chrome 99+, Safari 15.4+, Firefox 97+). Safe for production.

## @scope

### What It Solves

Scoped styles that apply only within a specific DOM subtree, with optional lower boundaries. Proximity-based specificity resolves conflicts based on DOM distance.

### Syntax

```css
/* Styles apply only inside .card, but NOT inside .card__footer */
@scope (.card) to (.card__footer) {
    a { color: oklch(0.50 0.20 250); }
    p { line-height: 1.6; }
}

/* Nested scopes for component variants */
@scope (.card--dark) {
    a { color: oklch(0.80 0.15 250); }
}
```

### Browser Support

Chrome 118+, Safari 17.4+. Firefox partial. Use as progressive enhancement.

## CSS Mixins (2026)

### What They Will Solve

Reusable blocks of CSS declarations without preprocessors. Currently in specification development, expected browser implementation in 2026.

### Proposed Syntax

```css
/* Define a mixin */
@mixin --flex-center {
    display: flex;
    align-items: center;
    justify-content: center;
}

@mixin --visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;
    border: 0;
}

/* Apply a mixin */
.hero {
    @apply --flex-center;
    min-height: 100dvh;
}

.sr-only {
    @apply --visually-hidden;
}
```

### Status

Specification in active development (CSS Working Group). Not yet in any browser. Plan for it but do not depend on it for production in 2025.

## Modern Layout Patterns

### Holy Grail Layout

```css
body {
    display: grid;
    grid-template:
        "header header header" auto
        "nav    main   aside" 1fr
        "footer footer footer" auto
        / 200px 1fr 200px;
    min-height: 100dvh;
}

header { grid-area: header; }
nav    { grid-area: nav; }
main   { grid-area: main; }
aside  { grid-area: aside; }
footer { grid-area: footer; }
```

### Responsive Grid Without Breakpoints

```css
.grid {
    display: grid;
    grid-template-columns: repeat(
        auto-fit,
        minmax(min(300px, 100%), 1fr)
    );
    gap: 1.5rem;
}
```

This single line creates a responsive grid that wraps from 4 columns to 1 column without any media queries.

### Full-Bleed Layout

```css
.content {
    display: grid;
    grid-template-columns:
        [full-start] minmax(1rem, 1fr)
        [content-start] min(65ch, 100% - 2rem)
        [content-end] minmax(1rem, 1fr)
        [full-end];
}

.content > * { grid-column: content; }
.content > .full-bleed { grid-column: full; }
```

### Sticky Header with Scroll Margin

```css
header {
    position: sticky;
    top: 0;
    z-index: 10;
    backdrop-filter: blur(10px);
    background: oklch(1 0 0 / 0.8);
}

/* Prevent anchor links from hiding behind sticky header */
[id] {
    scroll-margin-top: 5rem;
}
```

## Performance Best Practices

### content-visibility

```css
/* Skip rendering of off-screen sections */
.below-fold-section {
    content-visibility: auto;
    contain-intrinsic-size: auto 500px;  /* Estimated height to prevent layout shift */
}
```

Reduces initial rendering cost by 50-90% for long pages.

### will-change

```css
/* Hint to browser to optimize for transform animations */
.animated-element {
    will-change: transform;  /* Creates compositor layer */
}
/* Remove will-change after animation completes to free memory */
```

### CSS Containment

```css
.widget {
    contain: layout style paint;  /* Isolate rendering — changes inside don't trigger external reflows */
}
```

### Paint Containment for Scroll Performance

```css
.scroll-container {
    contain: paint;          /* Content outside bounds is not painted */
    overflow: auto;
    overscroll-behavior: contain;  /* Prevent scroll chaining */
}
```

## @starting-style — Entry Animations for Display Changes

### What It Solves

Before `@starting-style`, you couldn't animate an element from `display: none` to `display: block`. The browser had no "before" state to transition from. `@starting-style` defines the initial styles an element should have when it first appears in the DOM or transitions from `display: none`.

### Syntax

```css
/* Dialog that fades + scales in from nothing */
dialog[open] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 300ms ease, transform 300ms ease,
              display 300ms ease allow-discrete;
}

@starting-style {
  dialog[open] {
    opacity: 0;
    transform: scale(0.95);
  }
}

/* Exit animation — reversed */
dialog:not([open]) {
  opacity: 0;
  transform: scale(0.95);
  transition: opacity 200ms ease, transform 200ms ease,
              display 200ms ease allow-discrete;
}
```

### Key Rules

- `@starting-style` defines the state the element starts FROM when it first renders or un-hides
- Must be paired with `transition-behavior: allow-discrete` on the `display` property to animate display changes
- Works with `<dialog>`, `[popover]`, any element toggling `display: none`
- The exit animation uses the normal (non-starting) styles as the target

### Common Patterns

```css
/* Popover with slide-up + fade */
[popover]:popover-open {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 250ms ease, transform 250ms ease,
              overlay 250ms ease allow-discrete,
              display 250ms ease allow-discrete;
}

@starting-style {
  [popover]:popover-open {
    opacity: 0;
    transform: translateY(8px);
  }
}

/* Toast notification slide-in from right */
.toast.visible {
  translate: 0;
  opacity: 1;
  transition: translate 300ms cubic-bezier(0.16, 1, 0.3, 1),
              opacity 300ms ease,
              display 300ms allow-discrete;
}

@starting-style {
  .toast.visible {
    translate: 100%;
    opacity: 0;
  }
}
```

### Browser Support

Chrome 117+, Safari 17.5+, Firefox 129+. Progressive enhancement: elements simply appear without animation in unsupported browsers — functional, just not animated.

## transition-behavior: allow-discrete

### What It Solves

CSS properties like `display`, `overlay`, and `content-visibility` are discrete — they don't interpolate between values. `transition-behavior: allow-discrete` tells the browser to treat these as transitional: hold the "before" value for the first half of the transition, then snap to the "after" value.

### Syntax

```css
.element {
  transition: opacity 300ms ease,
              display 300ms ease allow-discrete;
}

/* Or as a standalone property */
.element {
  transition-property: opacity, display;
  transition-duration: 300ms;
  transition-behavior: normal, allow-discrete;
}
```

### Practical Usage

Always pair with `@starting-style` for entry animations. Without `allow-discrete`, the element snaps to `display: block` immediately, making the opacity transition invisible.

```css
/* Dropdown menu — complete open/close animation */
.dropdown-content {
  display: none;
  opacity: 0;
  transform: translateY(-4px);
  transition: opacity 200ms ease, transform 200ms ease,
              display 200ms ease allow-discrete;
}

.dropdown.open .dropdown-content {
  display: block;
  opacity: 1;
  transform: translateY(0);
}

@starting-style {
  .dropdown.open .dropdown-content {
    opacity: 0;
    transform: translateY(-4px);
  }
}
```

## interpolate-size: allow-keywords

### What It Solves

You cannot transition `height: 0` to `height: auto` in CSS — `auto` is a keyword, not a numeric value. `interpolate-size: allow-keywords` enables smooth transitions to and from keyword sizes (`auto`, `min-content`, `max-content`, `fit-content`).

### Syntax

```css
/* Enable globally */
:root {
  interpolate-size: allow-keywords;
}

/* Now height: auto transitions work */
.accordion-content {
  height: 0;
  overflow: hidden;
  transition: height 300ms ease;
}

.accordion-content.open {
  height: auto;  /* This now animates smoothly! */
}
```

### Accordion Example (No JavaScript for Height Calculation)

```css
:root {
  interpolate-size: allow-keywords;
}

details {
  border: 1px solid oklch(0.8 0 0);
  border-radius: 8px;
  overflow: hidden;
}

details > summary {
  padding: 1rem;
  cursor: pointer;
}

details > .content {
  height: 0;
  overflow: hidden;
  padding-inline: 1rem;
  transition: height 300ms ease, padding 300ms ease;
}

details[open] > .content {
  height: auto;
  padding-block: 1rem;
}
```

### Browser Support

Chrome 129+, Safari 18.2+. Behind flag in Firefox. Use as progressive enhancement — fallback is instant open/close which is functional.

## text-wrap: balance and text-wrap: pretty

### What They Solve

Headlines often have awkward line breaks — a single word on the last line ("orphan"). `text-wrap: balance` distributes text evenly across lines. `text-wrap: pretty` prevents orphans on the last line of paragraphs.

### Syntax

```css
/* Balanced headings — even line lengths */
h1, h2, h3 {
  text-wrap: balance;
}

/* Pretty paragraphs — no orphans on last line */
p {
  text-wrap: pretty;
}
```

### When to Use

| Property | Best For | Performance |
|----------|----------|-------------|
| `text-wrap: balance` | Headings, short text (< 6 lines) | Moderate — browser tries multiple layouts |
| `text-wrap: pretty` | Body text, paragraphs | Low — only adjusts last few lines |
| `text-wrap: stable` | Editable content | Prevents reflow while typing |

### Practical Example

```css
/* Global typography improvement */
:where(h1, h2, h3, h4, h5, h6, blockquote, figcaption, dt) {
  text-wrap: balance;
}

:where(p, li, dd) {
  text-wrap: pretty;
}
```

### Browser Support

`balance`: Chrome 114+, Safari 17.5+, Firefox 121+. `pretty`: Chrome 117+, Safari 17.4+, Firefox 128+. Safe to use — unsupported browsers simply use default text wrap.

## View Transitions API — Deep Dive

### Same-Document Transitions (SPA)

```javascript
// Trigger a view transition
document.startViewTransition(async () => {
  // Update the DOM
  updateContent();
});
```

```css
/* Default crossfade (works with zero CSS) */
::view-transition-old(root) {
  animation: fade-out 250ms ease;
}
::view-transition-new(root) {
  animation: fade-in 250ms ease;
}

/* Named transitions for specific elements */
.product-image {
  view-transition-name: product-hero;
}
.card-image {
  view-transition-name: product-hero;  /* Same name = morph between them */
}

/* Custom animation for the named transition */
::view-transition-old(product-hero) {
  animation: scale-down 300ms ease;
}
::view-transition-new(product-hero) {
  animation: scale-up 300ms ease;
}
```

### Cross-Document Transitions (MPA)

```css
/* Enable in both the outgoing and incoming pages */
@view-transition {
  navigation: auto;
}

/* Source page — shared elements */
.product-card {
  view-transition-name: product-hero;
}

/* Destination page — matching element */
.product-image {
  view-transition-name: product-hero;
}

/* Transition classes for outgoing page */
::view-transition-old(product-hero) {
  animation: 300ms ease both fade-and-scale-out;
}

/* Transition classes for incoming page */
::view-transition-new(product-hero) {
  animation: 300ms ease both fade-and-scale-in;
}
```

### Transition Types

```css
/* Conditional animations based on transition type */
document.startViewTransition({
  update: () => navigateForward(),
  types: ['slide-forward']
});

/* CSS responds to the type */
html:active-view-transition-type(slide-forward) {
  &::view-transition-old(root) {
    animation: slide-out-left 300ms ease;
  }
  &::view-transition-new(root) {
    animation: slide-in-right 300ms ease;
  }
}

html:active-view-transition-type(slide-back) {
  &::view-transition-old(root) {
    animation: slide-out-right 300ms ease;
  }
  &::view-transition-new(root) {
    animation: slide-in-left 300ms ease;
  }
}
```

### Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation-duration: 0.01ms !important;
  }
}
```

### Browser Support

Same-document: Chrome 111+, Safari 18+, Firefox 132+. Cross-document: Chrome 126+, Safari 18.2+. Use as progressive enhancement — navigation works without it, just without animation.

## field-sizing: content

### What It Solves

`<textarea>` and `<input>` elements have fixed sizes. `field-sizing: content` makes them grow or shrink to fit their content automatically, eliminating the need for JavaScript auto-resize.

### Syntax

```css
textarea {
  field-sizing: content;
  min-height: 2.5rem;   /* Minimum: one line */
  max-height: 20rem;    /* Maximum: prevent infinite growth */
}

input[type="text"] {
  field-sizing: content;
  min-width: 4ch;       /* Minimum width */
  max-width: 100%;
}

select {
  field-sizing: content; /* Select width matches longest option */
}
```

### Chat Input Example

```css
.chat-input {
  field-sizing: content;
  min-height: 2.5rem;
  max-height: 10rem;
  padding: 0.75rem 1rem;
  border-radius: 1.25rem;
  border: 1px solid oklch(0.85 0 0);
  resize: none;
  overflow-y: auto;
  transition: height 150ms ease;
}
```

### Browser Support

Chrome 123+, Firefox 132+. Not yet in Safari. Use JavaScript `auto-resize` as fallback.

## @scope — Scoped Styles

### What It Solves

Style encapsulation without Shadow DOM. `@scope` limits where CSS rules apply using a root selector and an optional lower boundary, preventing styles from leaking into nested components.

### Syntax

```css
/* Styles apply only within .card */
@scope (.card) {
  h2 { font-size: 1.25rem; }
  p { color: oklch(0.5 0 0); }
  a { color: oklch(0.5 0.2 260); }
}

/* With lower boundary — stop before nested cards */
@scope (.card) to (.card) {
  /* These styles apply to .card content but NOT to nested .card elements */
  p { margin-bottom: 0.75rem; }
}
```

### Proximity-Based Styling

`@scope` resolves conflicts by proximity — the nearest scope root wins:

```css
@scope (.light-theme) {
  p { color: oklch(0.2 0 0); }
}

@scope (.dark-theme) {
  p { color: oklch(0.9 0 0); }
}

/* If a .dark-theme is nested inside .light-theme,
   paragraphs inside .dark-theme get dark text */
```

### Practical Component Isolation

```css
/* Dashboard widget — scoped without Shadow DOM */
@scope (.widget) to (.widget__nested, .modal) {
  .title { font-weight: 600; font-size: 0.875rem; }
  .value { font-size: 2rem; font-weight: 700; }
  .chart { height: 120px; }
  .badge { font-size: 0.75rem; padding: 0.125rem 0.5rem; border-radius: 9999px; }
}
```

### Browser Support

Chrome 118+, Safari 17.4+. Not yet in Firefox. Use as progressive enhancement with `@layer` as fallback for specificity management.

## @property — Deep Dive

### What It Solves

CSS custom properties (`--my-color`) have no type checking — they're strings. `@property` registers them with a type (`<color>`, `<length>`, `<number>`, etc.), enabling animation, validation, and inheritance control.

### Animating Custom Properties

```css
/* Register the property with a type */
@property --gradient-angle {
  syntax: '<angle>';
  inherits: false;
  initial-value: 0deg;
}

/* Now it can be animated! */
.gradient-border {
  background: conic-gradient(from var(--gradient-angle), oklch(0.6 0.25 300), oklch(0.6 0.25 200), oklch(0.6 0.25 300));
  animation: spin 3s linear infinite;
}

@keyframes spin {
  to { --gradient-angle: 360deg; }
}
```

### Animated Gradient Background

```css
@property --color-start {
  syntax: '<color>';
  inherits: false;
  initial-value: oklch(0.6 0.2 260);
}

@property --color-end {
  syntax: '<color>';
  inherits: false;
  initial-value: oklch(0.7 0.15 300);
}

.hero {
  background: linear-gradient(135deg, var(--color-start), var(--color-end));
  transition: --color-start 600ms ease, --color-end 600ms ease;
}

.hero:hover {
  --color-start: oklch(0.65 0.25 200);
  --color-end: oklch(0.75 0.2 170);
}
```

### Progress Ring Animation

```css
@property --progress {
  syntax: '<number>';
  inherits: false;
  initial-value: 0;
}

.progress-ring {
  background: conic-gradient(
    oklch(0.6 0.2 260) calc(var(--progress) * 1%),
    oklch(0.9 0 0) calc(var(--progress) * 1%)
  );
  border-radius: 50%;
  mask: radial-gradient(circle, transparent 60%, black 61%);
  transition: --progress 1s ease;
}

.progress-ring[data-value="75"] {
  --progress: 75;
}
```

### Type-Safe Design Tokens

```css
@property --radius-md {
  syntax: '<length>';
  inherits: true;
  initial-value: 8px;
}

@property --color-primary {
  syntax: '<color>';
  inherits: true;
  initial-value: oklch(0.55 0.2 260);
}

/* Invalid values are rejected, falling back to initial-value */
.card {
  border-radius: var(--radius-md);      /* Guaranteed to be a <length> */
  background-color: var(--color-primary); /* Guaranteed to be a <color> */
}
```

### Browser Support

Chrome 85+, Safari 15.4+, Firefox 128+. Well supported. Use for any custom property that needs animation or type safety.

## scroll-snap-stop: always

### What It Solves

With `scroll-snap-type`, fast scroll gestures can skip past snap points. `scroll-snap-stop: always` forces the scroll to stop at every snap point, even during fast fling gestures.

### Syntax

```css
.carousel {
  scroll-snap-type: x mandatory;
  overflow-x: auto;
  display: flex;
  gap: 1rem;
}

.carousel-item {
  scroll-snap-align: start;
  scroll-snap-stop: always;  /* Cannot skip past this item */
  flex: 0 0 100%;
}
```

### When to Use

| Scenario | scroll-snap-stop |
|----------|-----------------|
| Image carousel (1 image at a time) | `always` — prevent skipping |
| Horizontal product scroll | `normal` — let users scroll fast |
| Full-page sections | `always` — each section is important |
| Timeline / story format | `always` — sequential content |

### Onboarding Flow Example

```css
.onboarding-container {
  scroll-snap-type: x mandatory;
  overflow-x: auto;
  display: flex;
  scrollbar-width: none; /* Hide scrollbar */
}

.onboarding-step {
  scroll-snap-align: center;
  scroll-snap-stop: always;
  flex: 0 0 100vw;
  min-height: 100dvh;
  display: grid;
  place-items: center;
  padding: 2rem;
}
```

### Browser Support

Chrome 75+, Safari 15+, Firefox 103+. Well supported.
