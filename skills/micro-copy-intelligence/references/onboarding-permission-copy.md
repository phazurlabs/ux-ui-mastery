# Onboarding and Permission Copy Templates

> 150+ production-ready onboarding and permission copy templates. Every template includes headline, body text, primary CTA, secondary CTA, and visual suggestion.

## Onboarding Copy Anatomy

Every onboarding screen should have:

```
[Visual/Illustration]    — Show, don't just tell
[Headline]               — The benefit or feature (brief, compelling)
[Body text]              — 1-2 sentences expanding on the headline
[Primary CTA]            — The next action
[Secondary CTA]          — Skip / Later / Alternative path
```

**Rules:**
- Lead with benefit, not feature name
- Keep onboarding to 3-5 screens max (completion drops 20% per extra screen)
- Always offer a skip option (never trap users)
- Use progressive disclosure — don't explain everything at once
- Personalize when possible ("Welcome, Alex" not "Welcome, user")

## 9. Permission Request Best Practices

### Pre-Permission Priming Rules

1. **Always explain the benefit before asking.** "Find restaurants near you" before the location prompt.
2. **Show, don't just tell.** Use a visual that demonstrates what the permission enables.
3. **Time it right.** Ask when the user needs the feature, not at first launch.
4. **Offer an alternative.** "Enter address manually" if they decline location.
5. **Never re-ask immediately.** If declined, wait for the next natural trigger.
6. **Respect the answer.** If they said "Not now", don't nag on every screen.

### Permission Denial Recovery

| # | Permission | Denial Message | Recovery CTA |
|---|-----------|---------------|-------------|
| 136 | Notifications | "You can enable notifications anytime in Settings." | Open Settings |
| 137 | Location | "Enter your location manually to see nearby results." | Enter location |
| 138 | Camera | "You can still upload photos from your library." | Upload from library |
| 139 | Contacts | "Invite friends by entering their email address." | Enter email |
| 140 | Calendar | "Add events manually to your in-app calendar." | Add event |
| 141 | Microphone | "You can use text chat instead of voice calls." | Open chat |
| 142 | Health | "Enter your data manually to track your progress." | Add manually |
| 143 | Photos | "Take a new photo with your camera instead." | Open camera |

### System Dialog Best Practices

- iOS: You get ONE chance for each permission. After denial, you can only direct to Settings.
- Android: Can re-request, but after two denials the system auto-denies.
- Web: Browser shows "Block" vs "Allow". If blocked, you must guide to browser settings.
- Always have a fallback for denied permissions — never dead-end the user.

## 11. Accessibility for Onboarding

- All onboarding screens must be navigable via keyboard
- Illustrations must have meaningful alt text (or `alt=""` if purely decorative)
- Auto-advancing carousels must have pause controls
- Step indicators must announce current step: "Step 2 of 5"
- Skip buttons must be keyboard-reachable (not hidden behind swipe gestures)
- Permission request screens must work with VoiceOver/TalkBack
- All text must meet WCAG 2.2 AA contrast ratios (4.5:1 for body, 3:1 for large text)
- Do not use color alone to indicate progress (use text labels alongside progress bars)
