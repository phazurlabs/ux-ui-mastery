But "fine" doesn't convert. "Fine" doesn't retain. "Fine" is what happens when you skip Empathize, Define, and Test — the three phases that separate products people love from products people tolerate.

Sumi fixes this. It embeds the entire UX design process into your terminal — cognitive psychology, NNG design thinking, production code patterns, accessibility standards, and 20 years of case studies. Every command traces to published research. Every output is copy-paste ready.

## The Journey

Six phases. Twenty-two steps. Each command suggests the next.

```
GROUND      /ground  →  /intent                                    know your process
DISCOVER    /taste  →  /inspo  →  /benchmark  →  /pulse            know your market
DIAGNOSE    /vibe-check  →  /brain-scan  →  /include  →  /flow     find what's broken
FORTIFY     /dark-scan  →  /trust-scan  →  /copy-check  →  /resp.  harden your standards
BUILD       /drip  →  /screen  →  /ship  →  /onboard  →  /extract  make the thing
LAUNCH      /roast  →  /remix  →  /judge  →  loop back              prove it works
```

Start anywhere. `/guide` shows you where you are and what comes next.

New to UX? Start at `/ground`. It takes 60 seconds. Already experienced? Jump to `/taste` or `/ship`.

## Getting best results

The golden rule: **give context, get precision.**

Every command works better when it knows *what* you're building, *who* it's for, and *what platform* it targets.

```
# Generic — Sumi guesses
/ship button

# Precise — Sumi tailors every decision
/ship button for a fintech iOS app, primary CTA for wire transfers,
must support Face ID confirmation, audience is 35-55 professionals
```

The second prompt gives Sumi enough to select trust-first color psychology, clinical motion, formal tone, generous touch targets, and iOS HIG conventions.

<details>
<summary><strong>Six prompting patterns</strong></summary>

**1. State your platform.** Sumi generates React/TypeScript, SwiftUI, and CSS. Default is React. Be explicit.

```
/ship toggle — SwiftUI with ViewModifiers
/ship dialog — vanilla CSS, popover API, no framework
```

**2. Name your tokens.** If you have a design system, tell Sumi so output integrates.

```
/ship card — tokens: --color-surface-primary, --space-md (16px),
--radius-lg (12px). Font: Inter. 4px grid.
```

**3. Specify your audience.** Audience changes touch targets, font sizes, contrast, density, and reading level.

```
/screen settings for users aged 65+
/screen dashboard for developers, keyboard-first
```

**4. Declare accessibility level.** Default is WCAG 2.2 AA.

```
/include — evaluate against WCAG 2.2 AAA
/brain-scan — prioritize cognitive load for users with ADHD
```

**5. Chain context.** Reference output from previous commands.

```
I ran /taste fintech and got Inter + DM Sans, blue-600 (#2563EB),
8px grid, medium radius. Now /ship button using that direction.
```

**6. Control depth.** Narrow or widen the output.

```
/vibe-check — only severity 3 and 4
/roast — every dimension, code fixes for every finding
/brain-scan — focus on cognitive load in the form only
```

</details>

<details>
<summary><strong>Mistakes that cost you</strong></summary>

| Mistake | Fix |
|---------|-----|
| `/ship button` with no context | Add sector, audience, platform, and token constraints |
| Auditing a description instead of code | Paste real code or point to a file path |
| Skipping `/taste` before building | Run `/taste` first — otherwise colors, type, and spacing default to generic |
| Running one audit and stopping | Layer at least `/vibe-check` + `/include` + `/brain-scan` for minimum coverage |
| Not specifying the platform | Say React, SwiftUI, or CSS explicitly |
| Ignoring "Next Steps" | Follow them — every command suggests the logical next command |

</details>

## How it works

You type a command. Claude loads the matching skill files — each one 10,000 to 30,000 words of research, patterns, and case studies.

Skills cross-reference. A component audit pulls from accessibility, cognitive psychology, and visual design simultaneously.

Commands chain. `/roast` points to `/remix`. `/taste` leads to `/inspo`. No dead ends.

Progressive disclosure keeps it fast. The full 480K+ words sit ready. Only the relevant slice activates.

## Install

### Marketplace (recommended)

```
/plugin marketplace add phazurlabs/sumi
/plugin install sumi@sumi-marketplace
```

Done. Works in every session.

### Manual

```bash
mkdir -p ~/.claude/plugins && cd ~/.claude/plugins
git clone https://github.com/phazurlabs/sumi.git
```

Add to `~/.claude/settings.json`:

```json
{
  "enabledPlugins": {
    "sumi": true
  }
}
```

### Verify

Restart Claude Code and run:

```
/taste saas
```

Commands appear as `/sumi:command-name`. Skills activate automatically — ask about any UX topic.
